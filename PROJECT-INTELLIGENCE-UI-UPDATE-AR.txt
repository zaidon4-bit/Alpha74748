تقرير تعديل Project Intelligence — واجهة المراحل والنتائج ورفع الملفات
===============================================================

ما تم تنفيذه
-----------
1) نقل الشرح الخاص بطريقة عمل Project Intelligence وتأثير إعدادات التفكير إلى بطاقة معلومات أسفل مساحة النتائج، وإزالة الملاحظة التوضيحية من صف إعدادات التفكير أعلى النموذج.
2) إزالة عناصر المخططين الثابتين من واجهة Project Intelligence، واستبدالهما بمسار مراحل أفقي داكن متحرك.
3) مراحل المسار مرتبطة بأحداث التنفيذ التي يرسلها الخادم: Thinking، Writing، Review، Fixing، ثم Complete. تبدأ نقطة Thinking بالنبض الأحمر، وتتحول المراحل النشطة اللاحقة إلى النبض الأخضر. بعد اكتمال المرحلة يتمدد خط محايد باتجاه النقطة التالية، وعند النجاح يظهر مؤشر الاكتمال الأخضر.
4) لا يتم تغيير تسلسل الكاتب/المراجع/التحسين أو عدد دورات المراجعة. التحريك يعتمد على أحداث المراحل نفسها، ولا يدّعي عرض التفكير الداخلي للمزوّد لحظة بلحظة.
5) إضافة رفع ملفات للمشروع من واجهة Project Intelligence. الحدود: 8 ملفات، 8 ميغابايت للملف، و20 ميغابايت للإجمالي.
6) تمرير محتوى الملفات النصية المدعومة إلى الكاتب والمراجع وجولات التحسين. ملفات ZIP تُقرأ في الذاكرة دون فكها على القرص. لا يتم تشغيل أي ملف مرفوع. تُستبعد الملفات الحساسة والمجلدات المولّدة والملفات الثنائية والمسارات غير الآمنة.
7) إضافة لوحة نتائج تظهر بعد اكتمال العملية (وتظهر أيضاً عند الفشل لعرض رسالة الخطأ)، وتحتوي الإجابة النهائية، والملفات الناتجة، ومراحل التنفيذ، وملفات الإدخال، وتفاصيل دورات المراجعة، وسجل الأحداث واستدعاءات API والاستخدام.
8) يمكن تغيير ارتفاع لوحة النتائج بمتحكم لمس، أو سحب حافتها رأسياً، أو فتحها بملء الشاشة.
9) كل ملف ناتج يظهر كبطاقة ظرف، وبها أزرار Open code وBack to file وDownload. أضيف تنزيل جميع الملفات في ZIP مع الحفاظ على مجلداتها وأسماء UTF-8.
10) استخدام مهارة Unlazy كمنهج قبول وتحقق: تحديد النتائج القابلة للفحص، مراجعة حدود الأمان، تشغيل الاختبارات، ثم تدقيق ما لم يمكن اختباره. لم يتم الادعاء بتشغيل CLI أو أدوات upstream غير المتاحة في بيئة التطبيق.

الفحوصات المنفذة
----------------
- python -m py_compile app.py project_intelligence.py : ناجح.
- python -m unittest discover -s tests -v : 40 اختباراً ناجحاً.
- node --check على JavaScript المستخرج من قالب الصفحة بعد إزالة تعبيرات Jinja : ناجح.
- اختبار JavaScript منفصل لتتابع Thinking → Writing → Review → Fixing : ناجح.
- اختبار مولّد ZIP من المتصفح ثم unzip -t : ناجح، وتم التحقق من قراءة المسارات الإنجليزية وUTF-8.
- فحص HTML ساكن: لا توجد معرّفات DOM مكررة، وعناصر المخططين القديمين غير موجودة داخل Project Intelligence، ولوحة النتائج مخفية قبل البدء.

حدود التحقق
------------
- لم يُشغّل خادم Flask أو اختبار HTTP حي؛ مكتبة Flask غير مثبتة في بيئة الفحص الحالية.
- لم يُجر اتصال فعلي بمزوّد API. يلزم تشغيل المشروع في بيئته المعتادة مع إعدادات API الصحيحة لتجربة التعاون الحي.
- لم يتوفر متصفح مرئي لاختبار العرض على هاتف فعلي؛ تم فحص HTML/CSS/JavaScript ساكناً، واختبار منطق المراحل ومولد ZIP بصورة منفصلة.
