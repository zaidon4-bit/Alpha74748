تقرير فحص نسخة Alpha AI للنشر على Render + Supabase

النتيجة: اجتازت الفحوصات الساكنة وفحوصات المحاكاة المحددة أدناه.

نجح:
- فحص صياغة Python لملفي app.py وmigrate_sqlite_to_supabase.py.
- التحقق من render.yaml ووجود Gunicorn وفحص صحة /healthz.
- اختبار طبقة توافق PostgreSQL مع ? placeholders وقراءة الصفوف بالاسم والفهرس عبر mock.
- اختبار إنشاء مخطط SQLite وترحيل عمود API القديم إلى مفتاح Google ومسار API.
- اختبار حفظ تعليمات النموذجين وتهيئة حساب المشرف من متغيرات البيئة.
- فحص وجود Qwen/Gemma بالاسمين الظاهرين المطلوبين، Thinking، UNLAZY، Web Search، API Failover، ذاكرة 80 رسالة، وUTF-8 SSE.
- التأكد من عدم وجود app.db أو ملفات .key أو .env حقيقية ضمن مجلد الحزمة.

لم يُختبر:
- اتصال فعلي بقاعدة Supabase الخاصة بالمستخدم.
- بناء وتشغيل Render الفعليان.
- مفاتيح Xkiro أو Google الحقيقية.
- اختبار دخول المستخدمين ورفع الملفات عبر موقع منشور.

السبب: لا تتوفر بيانات اعتماد Supabase/Render ومفاتيح المزودين في بيئة البناء، كما تعذر تنزيل الحزم الخارجية. لا تعتبر هذه النسخة منشورة بعد؛ يلزم ربط مستودع GitHub وإعداد متغيرات Render.

الأسرار المطلوبة في Render:
- DATABASE_URL: رابط Supabase PostgreSQL Session Pooler.
- ADMIN_USERNAME: الافتراضي admin.
- ADMIN_PASSWORD: كلمة مرور قوية يضعها مالك المشروع في Render، ولا تحفظ في GitHub.
- FLASK_SECRET_KEY: سر عشوائي ثابت؛ ينشئه Render في Blueprint.
- API_ENCRYPTION_KEY: سر ثابت؛ عند ترحيل قاعدة قديمة استخدم قيمة .api_encryption.key الأصلية بدلاً من قيمة جديدة.

مهم: لا ترفع app.db أو .api_encryption.key أو .flask_secret_key أو .env إلى GitHub.

ملحق فحوصات إصلاح التوافق — 2026-11-02

تم تنفيذه وفحصه محلياً:
- فحص صياغة Python لملف app.py وملف migrate_sqlite_to_supabase.py باستخدام py_compile.
- اختبار SQLite بمخطط legacy يحتوي على email وstatus وemail_verified وis_active وis_admin الإلزامية؛ نجح إنشاء حساب المدير والمستخدم، مع email_verified=false.
- اختبار مخطط التطبيق الحالي الذي لا يحتوي أعمدة البريد والحالة القديمة؛ بقي إنشاء المستخدم متوافقاً.
- اختبار أن العمود الإلزامي غير المعروف لا يُملأ بقيمة مخمّنة، بل يوقف الإنشاء برسالة واضحة قبل إدخال سجل غير سليم.
- اختبار محاكاة بيانات PostgreSQL information_schema والتحقق من توليد INSERT مع email وstatus وemail_verified.

التوافق لا يغيّر مخطط قاعدة البيانات ولا يحذف أو يعدّل السجلات القائمة. إذا وُجد عمود NOT NULL غير معروف ولا يملك DEFAULT، يتوقف إنشاء الحساب برسالة تحدد اسمه بدلاً من اختراع قيمة قد تفسد منطق الحساب أو الاشتراك.
