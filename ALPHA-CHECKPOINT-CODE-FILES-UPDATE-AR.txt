تحديث Alpha — نقاط الاستعادة وملفات أكواد المحادثة
====================================================

1) Project Checkpoints
----------------------
- تُنشأ نقطة استعادة تلقائياً عند انتهاء Project Intelligence بنجاح وإرجاع ملفات مولّدة.
- يمكن للمستخدم حفظ نقطة يدوياً من لوحة النتائج.
- تظهر آخر 30 نقطة استعادة للحساب، مع اسم المهمة وتاريخ الحفظ وعدد الملفات.
- يمكن تحميل ملفات أي نقطة قديمة إلى لوحة النتائج ثم معاينتها أو تنزيلها منفردة أو ضمن ZIP.
- لا تستبدل عملية التحميل ملفات على جهاز المستخدم أو على خادم التطبيق؛ إنها تستعيد مجموعة الملفات داخل Alpha، ويمكن تنزيل ZIP لتطبيقها يدوياً.
- تُحفظ النقاط لكل حساب على قاعدة البيانات، وتُنشأ قاعدة الجدول تلقائياً عند تشغيل init_db في SQLite أو PostgreSQL، دون حذف الجداول أو الرسائل القديمة.
- تُرفض مسارات traversal والمسارات المطلقة والملفات السرية المعروفة. الحد: 120 ملفاً، 2 MiB لكل ملف، و8 MiB إجمالاً.
- تُمنع النسخ المكررة المتطابقة عبر SHA-256، ويُحتفظ بأحدث 30 نقطة لكل حساب.

2) ملفات الكود في Chat
----------------------
- كتل Markdown fenced code تتحول تلقائياً إلى بطاقات ملفات.
- يُستخرج اسم الملف من تلميح المساعد عند توفره؛ وإلا يُنشأ اسم افتراضي بامتداد اللغة.
- تُمنع أسماء الملفات المكررة داخل الإجابة الواحدة بإضافة رقم تسلسلي.
- لكل ملف معاينة ونسخ وتنزيل منفصل.
- عند وجود كتل كود، يظهر زر لتنزيل جميعها ضمن ZIP واحد باسم Alpha-Code-Files.zip.

3) سجل المحادثات
----------------
سجل المحادثات الحالي بقي كما هو: قائمة محادثات محفوظة، بحث، بدء محادثة جديدة، وتنزيل TXT أو تصدير PDF/طباعة. لم تتم إضافة سجل مشاريع منفصل.

4) حدود التحقق
--------------
- اجتازت اختبارات Python الـ47 الموجودة في حزمة الاختبار.
- نجح py_compile لملفات Python.
- اجتاز ملف JavaScript فحص Node بعد إزالة قوالب Jinja فقط لأغراض الفحص.
- اختُبر إنشاء الجدول واستعلام الإدخال وحذف النسخ القديمة على SQLite في اختبار مستقل.
- لم يتوفر Flask في بيئة التعديل، لذلك لم يُشغّل خادم Flask ولم تُنفّذ اختبارات HTTP حية للمسارات الجديدة.
- لم يُختبر اتصال PostgreSQL/Supabase حيّاً. إنشاء الجدول فيه مُعرّف داخل init_db ويحتاج تأكيداً بعد النشر على قاعدة البيانات الفعلية.
