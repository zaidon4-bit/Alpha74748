تقرير ربط Alpha 3.1 Max مع Dev Code
===================================

1) مسار النموذج
- معرّف النموذج الخلفي: deepseek-v4.1-flash:free
- عنوان Token Harbor: https://tokenharbor.ai/v1/chat/completions
- المصادقة: Bearer API key محفوظ مشفراً في مسارات المستخدم.
- الاسم الظاهر للمستخدم بقي: Alpha 3.1 Max.

2) المواضع التي تستخدم المسار
- المحادثة الأساسية /chat عند اختيار Alpha 3.1 Max.
- Dev Code: الكاتب الافتراضي هو Alpha 3.1 Max، ويمكن أيضاً اختياره كمراجع.
- دورات Dev Code: المسودة الأولى، المراجعة المستقلة، ثم تحسين الكاتب.
- فحص الكود وإصلاحه في المحادثة يستخدمان مسار النموذج المحدد نفسه.
- استوديو البرمجة يرسل أوضاع التحليل المختارة ضمن تعليمات الطلب إلى النموذج المختار.

3) الاستدلال والتفكير
- تمت إضافة إعدادات الاستدلال إلى واجهة Dev Code أيضاً.
- يمكن إيقاف وضع الاستدلال أو تشغيله.
- مستويات التفكير المتاحة: low وhigh وmax.
- عند إيقاف الاستدلال، يرسل التطبيق thinking=disabled وreasoning_effort=none.
- إعدادات Dev Code تُمرر في كل استدعاء DeepSeek للكتابة والمراجعة والتحسين.
- إعدادات المحادثة الأساسية نفسها تُمرر إلى مراجعة الكود وإصلاحه التلقائيين.

4) حدود يجب معرفتها
- أوضاع استوديو البرمجة الست هي توجيهات تحليلية للنموذج، وليست حالياً تعريفات function tools تنفذها المنصة.
- التطبيق لا يشغّل كود المستخدم أو أوامر النظام تلقائياً.
- فحص ZIP ساكن، ومعاينة التعديل والتطبيق المنفصل محميان بتأكيد المستخدم.
- لم يُضف دعم حلقة function/tool-calling في عميل Token Harbor؛ لذلك لا ينبغي اعتبار المساعد حالياً وكيلاً ينفّذ أوامر أو يستدعي أدوات خارجية بنفسه.

5) التحقق
- نجح py_compile لملفات Python الرئيسية.
- نجحت اختبارات المشروع الـ37.
- نجح فحص صياغة كتل JavaScript الموجودة في app.py.
- نجح اختبار محلي بمحاكاة HTTP يؤكد إرسال معرّف النموذج الصحيح، وعنوان Token Harbor، والبث، وحالتي الاستدلال enabled/max وdisabled/none.
- لم يُنفّذ اتصال حي إلى Token Harbor؛ يلزم مفتاح صالح من لوحة المشرف لإجراء اختبار الشبكة الفعلي.

ملاحظة: الاختبارات المحلية لا تثبت توفر الحصة أو صلاحية المفتاح أو أن حساب Token Harbor يسمح بهذا النموذج لحظة التشغيل. استخدم زر فحص اتصالات Alpha بعد إدخال المفتاح.
