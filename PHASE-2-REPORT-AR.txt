Alpha AI — المرحلة الثانية: استوديو البرمجة الاختياري

الهدف:
إضافة واجهة اختيارية تمنح المستخدم تحكماً مباشراً في مساعدات البرمجة، بحيث لا تُفعّل تلقائياً ولا تعمل كعمليات خلفية.

ما تمت إضافته:
- لوحة «استوديو البرمجة» داخل واجهة المحادثة، بتصميم متجاوب مع الهاتف.
- ستة مفاتيح مستقلة: خريطة المشروع، تحليل تأثير التعديل، خطة الاختبارات، مراجعة التغييرات، طبيب السجلات، ومراجعة الأمان.
- جميع المفاتيح متوقفة افتراضياً.
- تفعيل كل الأدوات أو إيقافها دفعة واحدة، مع إمكانية التحكم بكل أداة منفردة.
- حفظ تفضيلات كل مستخدم محلياً على المتصفح، مع فصل المفتاح بحسب اسم الحساب.
- إرسال قائمة الأدوات التي اختارها المستخدم فقط مع طلب المحادثة الحالي.
- تحقق خادمي بقائمة سماح؛ يتم تجاهل أي أسماء أدوات غير معروفة أو قيم غير صالحة.
- إظهار الأدوات التي طُبقت على الإجابة بعد اكتمال الاستجابة.
- إضافة وحدة مستقلة coding_workbench.py واختبارات لها.

حدود السلوك والأمان:
- هذه مساعدات تحليل وتعليمات اختيارية للنموذج؛ ليست محركات فحص مستقلة أو أدوات تنفيذ برمجي.
- خريطة المشروع تعتمد على الملفات التي يرفقها المستخدم. لا تدّعي فحص مستودع غير مرفق.
- خطة الاختبارات تقترح الاختبارات والأوامر فقط؛ لا تشغّلها.
- مراجعة التغييرات تعرض اقتراحات وDiff؛ لا تطبق تغييرات على ملفات المستخدم.
- لا يوجد تشغيل أوامر Shell أو تنفيذ ملفات مرفوعة أو تثبيت حزم أو تعديل ملفات تلقائياً.
- عند إيقاف جميع الأدوات، لا يضاف أي قسم اختياري إلى System Prompt.
- تعليمات المشرف تبقى أعلى أولوية، وتبقى سياسة اللغة العربية في نهاية System Prompt.

المحافظة على المشروع:
- الملفات السابقة المحفوظة في الحزمة بقيت موجودة؛ لم يُحذف أي ملف سابق.
- الملف السابق الوحيد الذي تغير هو app.py لربط الواجهة وخيارات الطلب.
- أضيف coding_workbench.py وtests/test_coding_workbench.py.
- لم يتغير requirements.txt.
- لم يتغير مخطط SQLite أو PostgreSQL ولم تُضف جداول أو أعمدة.
- لم تتغير إعدادات Render أو Supabase أو مسارات API أو نظام تسجيل الدخول والاشتراكات أو منطق المحادثات والبث.
- بقيت وحدة التشفير AES-256-GCM من المرحلة الأولى كما هي.
- بقي ملف skills/unlazy/SKILL.md كما هو، وتم اتباع تعليمات الانضباط والتحقق الواردة فيه.

التحقق المنفذ محلياً:
- py_compile لملفات Python في المشروع؛ نجح.
- unittest: 10 اختبارات نجحت، منها 5 لاختبارات استوديو البرمجة و5 لاختبارات تشفير مفاتيح API.
- Node.js --check لسكريبت واجهة المحادثة بعد تصيير قالب Jinja؛ نجح.
- تصيير قالب Jinja والتحقق من عدم وجود معرّفات DOM مكررة؛ نجح.
- التحقق من ظهور الأدوات الست متوقفة افتراضياً، وأن لوحة الأدوات مخفية قبل فتحها؛ نجح.
- اختبار تركيب System Prompt من الدوال المستقلة: إعدادات OFF لا تضيف تعليمات الأدوات؛ واختيارات الأدوات تضيف تعليماتها فقط، مع بقاء تعليمات المشرف وسياسة العربية؛ نجح.
- التحقق من مقارنة ملفات الأرشيف: لا توجد ملفات سابقة محذوفة، والإضافات ملفا Python/اختبار جديدان (بالإضافة إلى هذا التقرير).

ما لم يُختبر:
- لم يُشغّل Flask بالكامل في بيئة الفحص لأن Flask غير مثبت فيها.
- لم يتم اختبار واجهة المتصفح الفعلية على جهاز Android أو على متصفح حي؛ تم فحص قالب HTML/DOM وJavaScript syntax.
- لم يتم الاتصال بـ Render أو Supabase أو مزودي الذكاء الاصطناعي الحقيقيين.
- لم يتم نشر الحزمة.

النتيجة:
المرحلة الثانية اجتازت اختبارات الوحدة والصياغة والتحقق الساكن المذكور أعلاه. يلزم تشغيل التطبيق بعد رفعه إلى بيئتك للتأكد من العرض الفعلي والاتصال بمزودي الخدمة.
