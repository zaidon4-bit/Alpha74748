تقرير المرحلة الثالثة — محرك فهم المشروع داخل Alpha
====================================================

الهدف
-----
إضافة فحص فعلي اختياري لبنية ملفات المشروع المرفقة، بحيث يستطيع المستخدم تشغيل «خريطة المشروع» عند الحاجة فقط، مع الإبقاء على الوظائف والملفات السابقة.

ما أُضيف
--------
1. ملف project_intelligence.py كمحلّل ساكن لملفات المشروع وأرشيفات ZIP.
2. ربط المحلّل بأداة «خريطة المشروع» الموجودة في استوديو البرمجة.
3. عرض بطاقة نتائج ضمن المحادثة تشمل ملخصاً، وعدد الملفات، واللغات، ونقاط الدخول المحتملة، وشجرة الملفات، وعلاقات الاستيراد المحتملة، ومسارات الويب المكتشفة.
4. إضافة اختبارات في tests/test_project_intelligence.py.
5. إظهار هوية المنتج للمستخدم باسم Alpha فقط، مع إبقاء المعرّفات الداخلية اللازمة للتوافق دون عرضها في الواجهة.

طريقة العمل
-----------
- لا يبدأ الفحص إلا إذا فعّل المستخدم «خريطة المشروع» وأرسل ملفات أو أرشيفاً.
- إذا كانت الأداة متوقفة، لا يستدعي التطبيق المحلّل.
- تتم قراءة محتويات الأرشيف من الذاكرة دون استخراجها على القرص.
- لا يستورد المحلّل ملفات المشروع ولا يشغّل شيفرتها ولا ينفذ أوامر نظام ولا يجري اتصالات شبكة.
- في ملفات Python، يستخرج المحلّل معلومات بنيوية من AST مثل أسماء الدوال والكلاسات والاستيرادات وبعض مسارات الويب.
- يتعامل مع أسماء الملفات ومحتوياتها كبيانات غير موثوقة، ويستخدم حدوداً للحجم والعدد.
- تُستثنى أسماء الملفات الحساسة ومجلدات الاعتماديات والملفات المولدة والمسارات غير الآمنة.
- الخريطة تحليل ساكن محدود، وليست إثباتاً بأن المشروع يعمل أو أن كل العلاقات قد اكتُشفت.

حدود الفحص الآمن
----------------
- حتى 800 مدخل داخل الأرشيف.
- حتى 100 ملف في القائمة المعروضة.
- حتى 80 ملف مصدر للتفاصيل.
- 256 كيلوبايت كحد أقصى لملف المصدر الواحد.
- 2 ميغابايت كحد أقصى لإجمالي بيانات ملفات المصدر المقروءة.
- التقرير النصي محدود إلى 12,000 حرف.

الملفات التي تغيرت
------------------
- app.py: ربط أداة خريطة المشروع بالمحلّل وإرسال بطاقة النتيجة في البث.

الملفات الجديدة
---------------
- project_intelligence.py
- tests/test_project_intelligence.py
- PHASE-3-REPORT-AR.txt

المحافظة على النسخة السابقة
---------------------------
- لم يُحذف أي ملف من نسخة المرحلة الثانية.
- بقيت جميع ملفات المرحلة الثانية كما هي، باستثناء app.py الذي أضيف إليه الربط المطلوب.
- لم يتغير requirements.txt أو Procfile أو render.yaml أو إعدادات قاعدة البيانات.
- لم تُجرَ أي ترحيلات على قاعدة البيانات.
- لم تُعدّل ملفات تشفير المرحلة الأولى أو وحدة استوديو البرمجة أو ملف مهارة Unlazy.

نتائج التحقق المنفذ
-------------------
- python -m py_compile للملفات الأساسية: نجح.
- python -m unittest discover -s tests -v: نجحت 18 اختبارات.
- فحص صياغة JavaScript المضمّن في صفحة المحادثة ولوحة الإدارة بواسطة node --check: نجح.
- فحص معرّفات HTML المكررة في صفحات الدخول والإدارة والمحادثة: لم تُكتشف معرّفات مكررة.
- فحص النص الظاهر في القوالب بعد إزالة تعليمات القوالب والسكريبتات: لم تظهر أسماء جهات أو نماذج خارجية.
- مقارنة ملفات ZIP: كل ملفات المرحلة الثانية الـ18 بقيت موجودة؛ التغيير الوحيد بين الملفات السابقة كان app.py؛ أضيفت الملفات الثلاثة المذكورة أعلاه.
- اختبار عدم تشغيل ملف Python مرفق: نجح، ولم يُنشأ ملف العلامة الاختباري.

ما لم يُختبر
------------
- لم يُشغّل خادم Flask فعلياً في هذه البيئة لأن اعتماديات التطبيق غير مثبتة هنا.
- لم يُنشر التطبيق على Render ولم يُختبر اتصال حي بقاعدة البيانات.
- لم يُجرَ اختبار بصري على هاتف فعلي أو متصفح حقيقي.
- فحص JavaScript كان فحص صياغة بعد إزالة تعبيرات القوالب فقط، وليس اختباراً تفاعلياً كاملاً للواجهة.

الحالة
------
المرحلة الثالثة مكتملة من ناحية التعديل والفحوص المحلية المذكورة، وتحتاج اختبار تشغيل حي بعد النشر قبل اعتبارها متحققة على بيئة الإنتاج.
